ToolkitCore
Foundation · Dependency Injection · Logging · Task management
01
Feature flags new
Local plist + remote JSON polling with Swift's @Observable macro so any SwiftUI view that reads a flag automatically re-renders when it changes. Flags are defined as a host-app enum — no stringly-typed keys, full autocomplete.
Usage
// 1. Define flags in your app target
extension ToolkitFlag {
    static let newCheckout   = ToolkitFlag("new_checkout")
    static let darkModeV2    = ToolkitFlag("dark_mode_v2")
}

// 2. Configure once at startup
Toolkit.flags.configure(
    remote: URL(string: "https://flags.myapp.com/v1.json")!,
    local: "FeatureFlags",          // plist in bundle
    refreshInterval: 300            // seconds
)

// 3. Read anywhere — SwiftUI auto-observes
if Toolkit.flags.isEnabled(.newCheckout) {
    showNewCheckout()
}
@ObservableSwiftUI reactiveremote pollingkill-switch support
02
Scoped DI containers extend
Child containers that inherit parent registrations but can override locally. Each scope is tied to a lifetime — user session, feature module, or screen — and deallocates all its registrations when closed. Multi-scene and modular app architectures need this.
Usage
let sessionScope = Toolkit.di.createScope(id: "userSession")
sessionScope.register(UserRepository.self) {
    SessionUserRepository(token: token)
}

// Teardown: all session-scoped objects deallocated
sessionScope.close()
03
PII-redacting logger destinations extend
Route the existing logger into os.Logger, a rolling file store, or a remote endpoint. PII redaction is declared via KeyPath — no regex, no manual scrubbing per call site.
Usage
ToolkitLogger.configure(
    level: .warning,
    destinations: [.osLog, .file("toolkit.log"), .remote(url: logsURL)],
    redacting: [\.userEmail, \.authToken, \.deviceId]
)
04
App lifecycle EventBus bridge new
Auto-publish UIApplication lifecycle events — foreground, background, memory warning, significant time change — into the existing EventBus. Modules can subscribe without importing UIKit.
Usage
for await _ in Toolkit.events.stream(of: AppDidEnterBackgroundEvent.self) {
    await pauseHeavyWork()
}

ToolkitNetworking
Interceptors · Circuit breakers · Auto-retry · URLSession
05
Offline request queue new
Persist failed requests to disk via Codable + FileManager. When ToolkitUtility's connectivity monitor fires a reconnect event, the queue replays in FIFO order, refreshing tokens via ToolkitAuth if needed. Entries expire after a configurable TTL.
Usage
var req = NetworkRequest(endpoint: .submitFeedback, body: feedback)
req.offlinePolicy = .queue(priority: .normal, ttl: 3600)

// Returns immediately — request queued if offline
try await Toolkit.networking.send(req)
06
In-flight request deduplication perf
Coalesce identical concurrent requests (same URL + HTTP method) into one real network call. All callers awaiting the same request receive the same response from a single AsyncStream continuation — ideal for profile images, config fetches, and shared data.
Usage
let config = NetworkConfig()
config.deduplicationStrategy = .byURLAndMethod
Toolkit.networking.configure(config)

// Both fire simultaneously — only one HTTP call made
async let a = Toolkit.networking.request(profileURL)
async let b = Toolkit.networking.request(profileURL)
07
Cache-control awareness extend
Honour Cache-Control, ETag, and Last-Modified response headers automatically. Back the cache store with URLCache with configurable memory and disk limits per request type.
Usage
var req = NetworkRequest(endpoint: .productCatalog)
req.cachePolicy = .respectServer    // .forceCache(ttl: 300) | .noCache
let products = try await Toolkit.networking.request(req, as: [Product].self)
08
Mock transport for testing new
A URLProtocol subclass that intercepts requests and returns fixture responses in XCTest. Register per test case — no global state pollution, no live server required. Supports simulating network errors and latency.
Usage
// In XCTestCase.setUp()
Toolkit.networking.useMockTransport { request in
    switch request.endpoint {
    case .login:
        return .success(Fixtures.loginResponse, statusCode: 200)
    case .profile:
        return .failure(.serverError(503))
    }
}
09
Upload progress + pause/resume extend
Wrap URLSessionUploadTask with an AsyncStream publisher exposing byte-level progress, pause, and resume controls. Resumable via URLSessionConfiguration.background for large files.
Usage
let upload = Toolkit.networking.upload(file: videoURL, to: .uploadVideo)

for await progress in upload.progressStream {
    progressBar.update(progress.fractionCompleted)
}

upload.pause()
upload.resume()

ToolkitAuth
Biometrics · Keychain · Session lifecycle
10
OAuth 2.0 / PKCE flow new
Full browser-based sign-in via ASWebAuthenticationSession. The PKCE code verifier and challenge are generated by existing ToolkitCrypto primitives. Tokens are stored in the existing Keychain layer. Expiry-based auto-refresh hooks into the ToolkitNetworking interceptor chain.
Usage
let provider = OAuthProvider(
    clientId: "com.myapp.client",
    authURL: "https://provider.com/auth",
    tokenURL: "https://provider.com/token",
    scopes: ["openid", "email", "profile"]
)

let tokens = try await Toolkit.auth.signIn(with: provider)
// Tokens auto-stored in Keychain, auto-refreshed on expiry
11
Passkey (WebAuthn) support new
Wrap Apple's AuthenticationServices passkey APIs for one-call registration and assertion. Falls back gracefully to Face ID / Touch ID when no passkey is enrolled. Private key material never leaves the Secure Enclave.
Usage
// Registration (new device)
let credential = try await Toolkit.auth.registerPasskey(
    username: user.email,
    relyingParty: "myapp.com"
)

// Sign-in
let assertion = try await Toolkit.auth.authenticateWithPasskey(
    relyingParty: "myapp.com"
)
12
Session anomaly detection extend
Bind sessions to a device fingerprint sourced from ToolkitUtility. Detect and act on device-mismatch, token reuse, or concurrent session limit — broadcast anomalies as typed EventBus events so any module can react.
Usage
Toolkit.auth.sessionPolicy = SessionPolicy(
    bindToDevice: true,
    maxConcurrentSessions: 3,
    onAnomaly: { anomaly in
        // .deviceMismatch | .tokenReuse | .concurrentLimitExceeded
        await Toolkit.auth.invalidateAllSessions()
    }
)
13
Auto token refresh interceptor extend
Detect 401 responses in the networking interceptor chain, silently refresh the access token using the stored refresh token, then replay the original request. Zero changes needed at call sites. Queues concurrent requests during the refresh window.
Usage
// Enable once — all requests benefit automatically
Toolkit.auth.enableAutoRefreshInterceptor(
    onRefreshFailed: { Toolkit.auth.signOut() }
)

ToolkitCrypto
AES-GCM · ChaChaPoly · Key management · CryptoKit
14
Secure Enclave key generation new
Generate P256 key pairs where the private key is hardware-bound and never exported. Biometric access control enforced via SecAccessControl. Public key is exported as Data for server-side verification.
Usage
let keyPair = try Toolkit.crypto.generateSecureEnclaveKey(
    tag: "com.myapp.signing",
    access: .biometryCurrentSet
)

let sig   = try Toolkit.crypto.sign(data: payload, with: keyPair.privateKey)
let valid = try Toolkit.crypto.verify(sig, data: payload, key: keyPair.publicKey)
15
Encrypted key-value vault new
A structured encrypted store where each value is AES-GCM encrypted with a per-vault key derived from the user's biometric. Built entirely on existing ToolkitCrypto abstractions — no third-party dependency. Survives app restart; vault locked on screen lock.
Usage
let vault = try Toolkit.crypto.openVault(name: "userSecrets", unlock: .biometry)

try vault.set(creditCard, forKey: "primaryCard")
let card: CreditCard = try vault.get(forKey: "primaryCard")
16
Certificate pinning helper extend
SHA-256 pin validation in a URLSessionDelegate shim. Plug directly into ToolkitNetworking's existing session configuration — no changes to request call sites.
Usage
Toolkit.crypto.pinnedCertificates = [
    PinnedCertificate(host: "api.myapp.com", sha256: "base64hash=="),
    PinnedCertificate(host: "cdn.myapp.com", sha256: "base64hash2=")
]
// Automatically enforced on all ToolkitNetworking requests

ToolkitUI
ThemeConfig · Components · HUD · Toast notifications
17
Skeleton loading modifier new
A ViewModifier that overlays shimmer-animated placeholder rectangles matching the live geometry of any view. No changes needed to existing components — apply as a one-liner. Shimmer respects prefers-reduced-motion / Accessibility settings.
Usage
// SwiftUI — works on any view
ProductCardView(product: product)
    .toolkitSkeleton(isLoading: viewModel.isLoading)

// Skeleton auto-matches the card's real layout
18
Bottom sheet / drawer new
Gesture-driven, multi-detent bottom sheet using UISheetPresentationController on iOS 16+ with a fully custom implementation as fallback. Bridged to SwiftUI via a ViewModifier. Exposes onDetentChanged and onDismiss callbacks.
Usage
// SwiftUI
ContentView()
    .toolkitBottomSheet(isPresented: $showFilters, detents: [.medium, .large]) {
        FilterPanelView()
    }

// UIKit
let sheet = ToolkitBottomSheet(content: filterVC, detents: [.medium, .large])
present(sheet, animated: true)
19
Design token system extend
Extend existing ThemeConfig into a full token system covering spacing grid, type scale, motion spring curves, and elevation levels. All existing components consume tokens instead of hard-coded values — one ThemeConfig change reshapes the entire app.
Usage
var theme = ThemeConfig()
theme.tokens = DesignTokens(
    spacing:   .grid(base: 4),
    typography: .scale(base: 16, ratio: 1.25),
    motion:    .spring(response: 0.35, damping: 0.85),
    elevation: [.card: 2, .modal: 8, .overlay: 16]
)
ThemeManager.shared.apply(theme)
20
Onboarding coach marks new
Sequence-aware spotlight overlays that highlight any anchored view. Steps are managed as a named flow stored in UserDefaults so they only show once. Dismisses via tap, swipe, or programmatically.
Usage
Toolkit.ui.coachMark(
    target: profileButtonAnchor,
    title: "Your profile",
    body: "Tap here to edit your details.",
    sequence: "onboarding",
    step: 1
)
21
Accessibility audit overlay new
Debug-only in-app overlay (activated by shake gesture or dev menu) that highlights contrast failures, missing accessibilityLabels, and touch targets below 44×44 pt. Uses UIAccessibility APIs — zero impact on release builds.
Usage
#if DEBUG
Toolkit.ui.enableAccessibilityAudit(
    checks: [.contrastRatio, .minimumTouchTarget, .missingLabel],
    overlay: .highlight    // or .log | .assert
)
#endif

ToolkitFormatter
Dates · Currencies · String transformations
22
Markdown → AttributedString renderer new
Parse CommonMark subset using Swift's built-in AttributedString(markdown:). Style overrides (font, link colour, code background) are exposed through the existing formatting pipeline. Output works directly in SwiftUI Text and UILabel.
Usage
let attributed = Toolkit.formatter.markdown(
    "**Hello** _world_ — tap [here](https://myapp.com)",
    style: MarkdownStyle(font: .body, linkColor: .accentColor)
)
Text(attributed)    // SwiftUI
23
Smart relative time extend
Context-aware relative time strings: "just now", "2 hours ago", "last Monday", "3 Jan". Uses RelativeDateTimeFormatter and DateComponentsFormatter with configurable verbosity thresholds — use .compact for cells, .full for detail views.
Usage
let label = Toolkit.formatter.relativeTime(
    from: post.createdAt,
    style: .smart,
    verbosity: .compact
)
// "2h ago"  |  "Yesterday"  |  "3 Jan"
24
Phone number formatting + validation new
Locale-aware E.164 formatting and region-specific validation using CNPhoneNumber heuristics. No external dependency. Supports national and international formats, and live input formatting as the user types.
Usage
let formatted = Toolkit.formatter.phoneNumber("+919876543210", locale: .current)
// → "+91 98765 43210"

let isValid = Toolkit.formatter.isValidPhoneNumber("+919876543210", region: "IN")
25
Measurement unit conversion new
Type-safe unit conversion using Swift's Measurement<UnitType> and MeasurementFormatter. Locale-correct output — automatically uses metric or imperial based on the device's region setting.
Usage
let dist = Measurement(value: 26.2, unit: UnitLength.miles)
let label = Toolkit.formatter.measurement(dist, convertedTo: .kilometers)
// → "42.16 km"

ToolkitUtility
Hardware · Connectivity · Device info
26
Thermal + performance budget manager new
Observe ProcessInfo.thermalState changes and emit tiered budget events — .ample, .reduced, .minimal — via the existing EventBus. Modules subscribe and gracefully degrade: disable heavy animations, pause background work, reduce frame rate.
Usage
Toolkit.utility.performanceBudget.onStateChange { budget in
    switch budget {
    case .ample:    enableHighQualityRendering()
    case .reduced:  disableHeavyAnimations()
    case .minimal:  pauseBackgroundTasks()
    }
}
27
Haptic feedback manager new
Typed, one-call wrapper over UIImpactFeedbackGenerator, UINotificationFeedbackGenerator, and CoreHaptics for custom AHAP patterns. Silently no-ops on devices without a Taptic Engine.
Usage
Toolkit.utility.haptics.trigger(.success)
Toolkit.utility.haptics.trigger(.impact(.heavy))
Toolkit.utility.haptics.trigger(.custom(sharpness: 0.8, intensity: 0.6))
28
App Store update nudge new
Poll the iTunes Lookup API via ToolkitNetworking. Compare the response against the app's CFBundleShortVersionString. Surface update prompts via the existing ToolkitUI toast or HUD — no custom UI code required.
Usage
Toolkit.utility.checkForUpdate(appId: "123456789") { result in
    if case .updateAvailable(let version) = result {
        Toolkit.ui.showUpdateBanner(availableVersion: version)
    }
}
29
Clipboard expiry new
Write sensitive content to UIPasteboard with a TTL. A Task.sleep fires after the interval and clears the pasteboard. Essential for OTP codes and auth tokens that shouldn't linger.
Usage
// Auto-clears from clipboard after 30 seconds
Toolkit.utility.clipboard.set("OTP: 482910", expiresIn: 30)

ToolkitPlugins
EventBus · Plugin registry · Extensibility layer
30
Typed async EventBus extend
Replace stringly-typed event names with Swift's any Sendable + protocol witness table. Subscriptions become AsyncStream-based for await loops — fully structured-concurrency-compatible, no callback registration/deregistration.
Usage
// Define — compile-time safe, discoverable
struct UserLoggedIn: ToolkitEvent { let userId: String }

// Publish
Toolkit.events.publish(UserLoggedIn(userId: session.userId))

// Subscribe — structured concurrency
for await event in Toolkit.events.stream(of: UserLoggedIn.self) {
    await updateUI(for: event.userId)
}
31
Plugin dependency declarations extend
Plugins declare a static var dependencies array of other plugin types. The registry performs a topological sort at startup so initialisation order is always correct — no more manual ordering, no runtime crashes from missing dependencies.
Usage
struct AnalyticsPlugin: ToolkitPlugin {
    static var dependencies: [any ToolkitPlugin.Type] = [AuthPlugin.self]
    // Guaranteed to initialise after AuthPlugin
}

ToolkitSync new module
CoreData · SwiftData · Offline-first · Conflict resolution
✦
New module proposal. ToolkitSync bridges local CoreData / SwiftData stores with a REST backend — handling dirty tracking, conflict resolution, and background sync. Depends on ToolkitNetworking + ToolkitAuth — no new third-party dependencies.
32
Delta sync engine new
A @SyncedModel macro attaches to NSManagedObject or SwiftData @Model and tracks which fields are dirty since the last successful sync. Only changed records are serialised and transmitted per cycle — no full payload on every sync.
Usage
@SyncedModel
class Note: NSManagedObject {
    @NSManaged var title: String
    @NSManaged var content: String
}

Toolkit.sync.configure(
    store: persistentContainer,
    remote: RESTSyncAdapter(baseURL: apiURL),
    conflictStrategy: .lastWriteWins
)
try await Toolkit.sync.syncNow()
33
Pluggable conflict resolution new
Three built-in strategies — .lastWriteWins, .serverWins, .clientWins — plus a custom closure for field-level merge logic. Conflicts are broadcast as typed EventBus events so the UI can surface a resolution prompt to the user.
Usage
Toolkit.sync.conflictStrategy = .custom { local, remote in
    // Return whichever version to keep
    local.updatedAt > remote.updatedAt ? local : remote
}

for await conflict in Toolkit.events.stream(of: SyncConflictEvent.self) {
    showResolutionUI(for: conflict)
}
34
Background sync via BGAppRefreshTask new
Register once at app startup. iOS schedules background sync using BGAppRefreshTask. Token refresh is delegated to the ToolkitAuth interceptor before each cycle — the sync engine never touches auth logic directly.
Usage
// Register once in AppDelegate / App.init
Toolkit.sync.enableBackgroundSync(
    taskIdentifier: "com.myapp.sync",
    minimumInterval: 900   // 15 min
)

// Status observable
Toolkit.sync.statusPublisher
    .sink { status in /* .idle | .syncing | .error(Error) */ }

ToolkitAnalytics new module
Privacy-first · Consent gate · Adapter pattern · Funnels
✦
New module proposal. ToolkitAnalytics is a consent-first event tracking engine with an adapter pattern for any backend — Mixpanel, PostHog, Amplitude, or your own. All network calls go through ToolkitNetworking, inheriting circuit breakers and offline queuing.
35
Consent-gated event tracking new
All tracking is paused until explicit user consent is recorded. Events fired before consent is granted are buffered locally and flushed retroactively (or discarded, configurable). Supports GDPR, CCPA, and App Tracking Transparency flows out of the box.
Usage
Toolkit.analytics.configure(
    adapters: [MixpanelAdapter(token: "abc"), PostHogAdapter(key: "xyz")],
    consent: .requireExplicit,
    bufferIfNoConsent: true
)

Toolkit.analytics.setConsent(granted: true)   // flushes buffer

Toolkit.analytics.track(.custom("purchase_completed", properties: [
    "amount": 49.99, "currency": "INR", "items": 3
]))
36
Funnel + retention analysis new
Define multi-step named funnels in code as a sequence of event names. The SDK tracks entry, completion, and per-step drop-off automatically. No dashboard configuration needed — funnel definitions live in Swift alongside the features they describe.
Usage
Toolkit.analytics.defineFunnel("onboarding", steps: [
    .event("signup_started"),
    .event("email_verified"),
    .event("profile_completed"),
    .event("first_purchase")
])

// SDK auto-tracks progress whenever these events fire
37
Auto-instrumented performance events new
View load time, network latency per endpoint, and cold app launch duration tracked automatically via UIViewController swizzling and os.signpost intervals. Zero call-site changes — enable once and all screens are instrumented.
Usage
Toolkit.analytics.enableAutoInstrumentation(
    track: [.screenLoad, .networkLatency, .appLaunch],
    sampleRate: 1.0   // 0.0 – 1.0
)
// Events like "screen_loaded" { screen: "HomeView", duration_ms: 84 }
// appear in your analytics backend automatically
